Хід роботи


1. Розробити будову програмної системи. 
Стек: C# + ASP.NET Core Web API (стандарт для сучасних серверних систем).
База даних: SQLite. Рішення: використання файлової БД спрощує розгортання та переносимість проекту.
ORM: Entity Framework Core. Рішення: використання підходу Code-First (спочатку код, потім база) для автоматизації створення структури таблиць.
Архітектура: REST API. Використання JSON як формату обміну даними забезпечує сумісність із будь-якими клієнтами (IoT, мобільні програми, браузери).
Система розділена на три логічні шари:
* Layer 1: Models (Сутності) — класи, що описують структуру даних (Поїзд, Користувач, Станція).
* Layer 2: Data (Доступ до даних) — реалізований за допомогою Entity Framework Core для взаємодії з базою даних SQLite.
* Layer 3: Controllers (API) — обробники HTTP-запитів, які забезпечують взаємодію між клієнтом і сервером.
2. Створити UML діаграму прецедентів для серверної частини системи.
Для серверної частини визначено три основні ролі (актори):
* Адміністратор: додавання/редагування поїздів, управління станціями та розкладом.
* Клієнт: реєстрація, аутентифікація, перегляд списку поїздів та їхнього статусу (затримки), перегляд історії.
* IoT-клієнт (Датчик): автоматичне оновлення поточного місцезнаходження поїзда через API.

3. Створити ER діаграму даних. 
База даних містить такі основні сутності та зв'язки:
* Users: зберігає дані користувачів (Id, Name, Email, Password).
* Trains: інформація про поїзди (Id, Number, CurrentStationId, DelayMinutes).

6  Розробити функції роботи з БД (ORM або CoRM тощо). 
Робота з базою даних реалізована через ORM Entity Framework Core.
* Створено клас AppDbContext, який описує набір таблиць (DbSet).
* Використовується механізм Migrations для керування структурою БД.
* Для початкового заповнення бази використано метод OnModelCreating (Seeding), що автоматично додає 5 поїздів та станції при першому запуску.
7 Розробити API (REST або GraphQL, gRPC тощо) для взаємодії серверної частини з клієнтами. 
Для взаємодії з клієнтами розроблено REST API. Використовуються стандартні методи HTTP:
* GET /api/trains — отримання списку поїздів.
* POST /api/auth/register — реєстрація користувача.
* POST /api/Auth/login — вхід користувача.
* POST /api/trains/{id}/update-location — прийом 
Взаємодія з клієнтами: Метод Register з AuthController і GetTrains з TrainsController. Сервер приймає запрос и віддає відповідь. 
код:
[HttpPost("register")]
public async Task<IActionResult> Register(string name, string email, string password)
{
    if (await _context.Users.AnyAsync(u => u.Email == email))
    {
        return BadRequest("Користувач з такою поштою є!");
    }
    var newUser = new User
    {
        Name = name,
        Email = email,
        Password = password,
        IsAdmin = false // По умолчанию все — обычные юзеры
    };


    _context.Users.Add(newUser);
    await _context.SaveChangesAsync();


    return Ok(new { message = "Реєстрація успішна!", userId = newUser.Id });
}

public async Task<ActionResult<IEnumerable<Train>>> GetTrains()
{
    return await _context.Trains
        .Include(t => t.Route) 
        .ThenInclude(rs => rs.Station) 
        .ToListAsync();
}

10. Тестування
Проведено два етапи тестування:
1. Тестування взаємодії з БД: При запуску програми перевірено наявність файлу transport.db та успішне зчитування початкових даних про поїзди.
