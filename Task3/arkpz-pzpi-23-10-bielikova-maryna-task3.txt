1. Текстовий опис інженерних рішень
У межах розробки серверної частини було впроваджено такі рішення:
* Модульна архітектура: Контролери розділені за функціональним призначенням: AuthController (клієнтські функції), TrainsController (адміністрування) та SensorController (обробка даних від IoT).
* Рольова модель доступу: Реалізовано перевірку прав доступу на основі параметрів запиту. Методи редагування та видалення доступні лише для користувачів із роллю Admin.
* Автоматизація розрахунків: Бізнес-логіка сервера самостійно обчислює відхилення від графіка, порівнюючи плановий час із бази даних та фактичний час, отриманий від датчика.
* Каскадна цілісність: Налаштовано зв'язки «один-до-багатьох» між поїздами та маршрутами, що забезпечує автоматичне видалення розкладу при видаленні транспортного засобу.

Бізнес-логіка (Математична обробка даних)
Цей фрагмент відповідає за обчислення затримки: Delay = Tактуальне- Tзарозкладом
SensorController.cs
if (TimeSpan.TryParse(actualTime, out var tActual) && 
    TimeSpan.TryParse(schedule.ScheduledArrival, out var tScheduled))
{
    // Розрахунок різниці в хвилинах
    int delay = (int)(tActual - tScheduled).TotalMinutes;
    
    // Якщо приїхав пізніше — фіксуємо затримку, інакше — 0
    train.DelayMinutes = delay > 0 ? delay : 0;
}


Адміністрування серверної частини
Приклад методу для точкового редагування розкладу:
TrainsController.cs
[HttpPut("schedule/edit-stop/{stopId}")]
public async Task<IActionResult> EditStop(int stopId, string newArrival, string newDeparture, int newOrder, string role)
{
    if (role != "Admin") return Forbid(); // Перевірка прав адміністратора


    var stop = await _context.RouteStops.FindAsync(stopId);
    if (stop == null) return NotFound();


    stop.ScheduledArrival = newArrival;
    stop.ScheduledDeparture = newDeparture;
    stop.Order = newOrder;


    await _context.SaveChangesAsync(); // Збереження змін у БД
    return Ok("Дані оновлено");
}
