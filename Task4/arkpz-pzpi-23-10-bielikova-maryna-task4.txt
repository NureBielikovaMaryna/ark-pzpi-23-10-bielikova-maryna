1. Текстовий опис інженерних рішень
Для реалізації ІоТ-клієнта було обрано платформу ESP32, оскільки вона має вбудований Wi-Fi модуль та достатньо потужності для роботи з протоколом HTTPS.
Інженерні рішення:
* Протокол передачі даних: Використано HTTP POST, що є стандартом для передачі стану датчиків на сервер.
* Безпека: Використано бібліотеку WiFiClientSecure з налаштуванням setInsecure() для роботи з ngrok без необхідності постійного оновлення SSL-сертифікатів у пам'яті мікроконтролера.
* Синхронізація часу: Для точності даних використано протокол NTP (Network Time Protocol). Клієнт самостійно отримує актуальний час, що дозволяє серверу точніше розраховувати затримку поїзда.
* Обхід обмежень: Додано спеціальні HTTP-заголовки (ngrok-skip-browser-warning), що дозволяє автоматизованому пристрою проходити через захисні сторінки ngrok.

В. Бізнес-логіка обробки даних на стороні сервера (Математична обробка):


using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;
using WebApplication1.Data;
namespace WebApplication1.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class SensorController : ControllerBase
    {
        private readonly AppDbContext _context;
        public SensorController(AppDbContext context) => _context = context;


        // обн где знах поезд
        
        [HttpPost("update")]
        public async Task<IActionResult> UpdateLocation(
    [FromQuery] int trainId,
    [FromQuery] int stationId,
    [FromQuery] string actualTime)
        {
             
            var train = await _context.Trains
                .Include(t => t.Route)
                .FirstOrDefaultAsync(t => t.Id == trainId);


            if (train == null) return NotFound("Поїзд не знайдено");


            // поиск в распис станц
            var schedule = train.Route.FirstOrDefault(rs => rs.StationId == stationId);


            if (schedule != null)
            {
                train.CurrentStationId = stationId; //местопол


                // задержка мат
                if (TimeSpan.TryParse(actualTime, out var tActual) &&
                    TimeSpan.TryParse(schedule.ScheduledArrival, out var tScheduled))
                {
                    int delay = (int)(tActual - tScheduled).TotalMinutes;
                    train.DelayMinutes = delay > 0 ? delay : 0;
                }
            }


            await _context.SaveChangesAsync();
            return Ok(new
            {
                status = "Дані отримано від датчика",
                train = train.Number,
                delay = train.DelayMinutes
            });
        }
    }
}




Висновок:В якості інженерного рішення обрано архітектуру 'Тонкий клієнт'. ІоТ-пристрій виконує роль збирача даних: він фіксує точний час події за допомогою протоколу NTP та передає його на Web API через шифрований канал (HTTPS/ngrok). Вся складна математична логіка (пошук розкладу, розрахунок затримки та оновлення бази даних SQLite) винесена на сервер, що дозволяє економити ресурси мікроконтролера та забезпечує централізоване зберігання даних.
